# MXL Column Editor

Программа для массового редактирования колонок регистров в **табличных документах
1С:Предприятия** (`.mxl`) с точным предпросмотром, который рисует сама 1С.

Написана для сопровождения эталонных макетов: когда в конфигурации у регистра
появляется, исчезает или переименовывается колонка, за ней должны последовать все
`.mxl`-эталоны в наборе тестов. Делать это вручную на сотне файлов долго, и легко
ошибиться.

- Добавление, переименование и удаление колонки в любом регистре сразу по всей папке
- Видно, что именно изменится в каждом файле, ещё до записи
- Предпросмотр печатной формы ровно в том виде, в каком её рисует 1С, прямо в окне
- Каждый запуск сопровождается резервной копией и побайтовой проверкой

Только стандартная библиотека Python и Tkinter — для самого редактирования не нужно
ничего доустанавливать. Для коллег без Python можно собрать один `.exe` под Windows.

## Быстрый старт

**С Python:**

```bash
git clone https://github.com/SergiosZZz/mxl-column-editor.git
cd mxl-column-editor
python mxl_column_editor.py
```

**Без Python** — скачайте релиз, распакуйте и запустите `MXL Column Editor.exe`.

Всё, кроме предпросмотра через 1С, работает сразу. Для предпросмотра нужна
установленная 1С — см. [Настройка рендера 1С](#настройка-рендера-1с).

## Работа с программой

Окно состоит из бокового меню с четырьмя разделами; строка состояния и кнопка
**Apply changes** всегда на виду. Рядом с каждым разделом показан счётчик, чтобы
было понятно, сколько всего загружено.

### 1. Рабочая папка

*Browse…* выбирает папку с `.mxl`-файлами и сразу её сканирует. Вложенные папки не
просматриваются. После успешного сканирования программа переходит к регистрам.

### 2. Регистры

Все регистры, найденные в папке: в скольких файлах встречается каждый и сколько у
него различающихся имён колонок. Выберите регистр — справа появится список его
колонок.

**Двойной щелчок по колонке** сразу открывает окно добавления изменения: регистр и
колонка уже подставлены как опорные, курсор стоит в поле нового имени. Обычно это
самый быстрый способ создать правило.

### 3. Изменения

Очередь изменений. Кнопка *+ Add modification* открывает окно с тремя вкладками.

**Add column** — добавить колонку

| Поле | Значение |
|---|---|
| Register | Регистр, например `Inventory and expenses` |
| Position | `after` или `before` опорной колонки |
| this column | Опорная колонка, например `Posting content` |
| New column | Заголовок новой колонки |
| Value in data rows | Значение во всех строках данных (можно оставить пустым) |

По мере ввода показывается **итоговый порядок колонок**, а также предупреждение,
если такое имя уже есть или опорная колонка не найдена.

**Rename column** — переименовать. Меняется только ячейка заголовка: порядок колонок,
ширины, нумерация и все строки данных остаются ровно такими, какими были, а разница
в байтах — буквально один текст заголовка.

**Delete column** — удалить колонку вместе со всеми ячейками под ней; оставшиеся
колонки смыкаются.

Все три вида отображаются в очереди со столбцом Action и могут применяться за один
проход. Поля регистра и колонки — редактируемые списки, поэтому можно ввести имя,
которого сканирование не нашло: это удобно, когда колонка есть пока не во всех
файлах.

> Добавление колонки с последующим удалением возвращает файл байт в байт, как и
> переименование туда и обратно. Оба сценария входят в набор тестов.

### 4. Файлы

Все `.mxl` с размером, количеством регистров, шириной самого широкого из них и тем,
что с этим файлом сделают ваши изменения. Цветовая разметка: зелёный — колонки будут
добавлены или удалены, янтарный — опорная колонка не найдена, серый — регистра нет,
красный — файл не разобрался.

Столбец **Use** задаёт область применения. Флажок *Apply to all files* включён по
умолчанию. Если его снять, изначально не выбрано ничего: список становится
множественного выбора, и файлы отмечаются осознанно.

- **Ctrl+щелчок** — добавить файл к выделению, **Shift+щелчок** — диапазон
- **Правая кнопка мыши** — *Include in the run*, *Exclude from the run*, *Toggle*,
  *Include every eligible file*, *Include none*, а также команды предпросмотра
- **Пробел** — переключить всё выделенное
- щелчок по ячейке **Use** переключает один файл

Файлы, в которых ничего не изменится, показаны прочерком и не выбираются.

### Применение изменений

Кнопка **Apply changes** сначала уточняет область применения, затем перезаписывает
файлы на месте, показывая прогресс и состояние по каждому файлу. Панель журнала
внизу разворачивается для подробностей и открывается автоматически при запуске.

Три средства защиты, все включены по умолчанию:

- **Back up originals** — перед записью копирует все обрабатываемые файлы в
  `_mxl_backup_<дата_время>\` внутри рабочей папки.
- **Skip if column already exists** — повторный запуск не создаёт дубликатов.
- **Verify after writing** — каждый записанный файл заново разбирается и сверяется с
  резервной копией: не изменилось ли количество строк, стоит ли новая колонка ровно
  один раз и в нужном месте, во всех ли строках данных нужное значение, не изменился
  ли текст существующих ячеек, совпадают ли побайтово заголовок и «хвост» документа.

## Предпросмотр печатной формы

Выберите файл и нажмите **Preview printform** (либо дважды щёлкните по нему). В окне
две вкладки:

- **1C preview** — открывается первой и сразу запускает рендер: документ передаётся
  1С:Предприятию и отображается ровно так, как рисует платформа, прямо в окне.
  Кнопка *Open in browser* открывает тот же результат в браузере.
- **Grid** — встроенная текстовая сетка всего документа. Мгновенно, ничего
  доустанавливать не нужно; добавленные ячейки подсвечиваются зелёным.

Если в очереди есть изменения, обе вкладки предлагают переключатель **With
modifications** / **Original** — можно сравнить и увидеть, что именно поменялось.
Переключение автоматически перезапускает рендер. Изменения применяются к *временной
копии*, поэтому предпросмотр никогда не трогает файл на диске.

## Настройка рендера 1С

Предпросмотр — это не собственная реализация вёрстки MXL: документ передаётся
платформе, и всю работу делает она:

```bsl
ТабличныйДокумент = Новый ТабличныйДокумент;
ТабличныйДокумент.Прочитать(ИмяВходногоФайла);
ТабличныйДокумент.Записать(ИмяВыходногоФайла, ТипФайлаТабличногоДокумента.HTML);
```

`ТабличныйДокумент.Прочитать` недоступен в тонком клиенте, поэтому вызов выполняется
на сервере, а значит нужна информационная база. При первом запуске программа
создаёт небольшую служебную ИБ из вложенного `onec\MxlRendererTemplate.dt` и дальше
использует её повторно.

**Укажите клиент:** *Tools → 1C:Enterprise renderer…* — выберите тонкий клиент
`1cv8c.exe`. Рядом с ним должен лежать `1cv8.exe`: он однократно используется для
создания служебной ИБ. Кнопка *Auto-detect* ищет в обычных каталогах
`Program Files\1cv8\<версия>\bin`.

### Сборка MxlToHtmlService.epf

Без неё каждый предпросмотр запускает новый процесс 1С: несколько секунд ожидания и
мелькание окна. **Резидентная** обработка запускается один раз и дальше обслуживает
очередь, поэтому последующие предпросмотры почти мгновенные. Её нужно один раз
собрать в Конфигураторе:

1. Создайте новую внешнюю обработку.
2. Добавьте **управляемую форму**.
3. В свойствах обработки назначьте её **основной формой** (`ОсновнаяФорма`).
4. Откройте вкладку **Модуль** этой формы — именно *модуль формы*, а не модуль
   объекта — и вставьте целиком
   [`onec/MxlToHtmlService.bsl`](onec/MxlToHtmlService.bsl).
5. **Свяжите событие ПриОткрытии.** Процедура, просто *названная* `ПриОткрытии`
   (`OnOpen`), обработчиком формы не становится: без этого шага форма откроется,
   код не выполнится, и никакой ошибки нигде не будет. Выделите корневой элемент
   формы, нажмите **F4** и в разделе **События** щёлкните по лупе рядом с
   **ПриОткрытии**, чтобы в поле появилось имя процедуры.
6. Сохраните как `MxlToHtmlService.epf` в папку `onec\`.

Затем выполните *Tools → 1C renderer diagnostics…* — диагностика пройдёт весь путь и
покажет, на чём он обрывается. Подробности — в [`onec/README.md`](onec/README.md).

## Сборка .exe для Windows

На машине с Windows и Python дважды щёлкните **`build_windows_exe.bat`**. Скрипт
установит PyInstaller, упакует файлы из `onec\` и создаст:

```
dist\MXL Column Editor.exe
dist\onec\                     пересобираемые .epf
```

Передавайте коллегам всю папку `dist\`. Один `.exe` тоже работает — внутри лежит своя
копия `onec\`, — но если отдать папку, `.epf` можно пересобрать в Конфигураторе и
просто положить рядом, не пересобирая программу: файлы рядом с `.exe` имеют
приоритет над вложенными.

Если нужен встроенный предпросмотр, поставьте `tkinterweb` **до** сборки: собранная
программа уже не сможет ничего доустановить через pip.

> При первом запуске возможно ложное срабатывание антивируса — сборки PyInstaller
> часто попадают под эвристики.

## Решение проблем

Начните с *Tools → 1C renderer diagnostics…*. Диагностика покажет клиент, обе
обработки, информационную базу, запустит временный резидентный сеанс, отрендерит
реальный файл и выведет текст ошибки от самой 1С, если что-то пойдёт не так.

| Симптом | Причина |
|---|---|
| Предпросмотр открывается в браузере вместо окна | Не установлен `tkinterweb` либо он установлен в другой Python. В журнале при запуске выводится путь к интерпретатору и точная команда установки. |
| Диагностика: «the resident processor never reported ready», нет `startup.log` | Не связано событие `ПриОткрытии` (шаг 5 выше) либо форма не назначена основной. |
| Диагностика: `startup.log` обрывается на середине | Ошибка на одном из шагов; в трассировке указано, на каком. |
| На экране висит окно 1С | Так и должно быть при резидентном сеансе — оно сворачивается автоматически. Отключается через *Tools → Keep 1C running between previews*. |
| При применении ничего не происходит | Посмотрите раздел Files: файлы с прочерком менять нечего. |
| Файл «could not be parsed» | Это не документ MOXCEL либо он повреждён. |

## Как это устроено

`.mxl` — это не зазипованный XML, а текстовый формат с вложенными фигурными скобками,
начинающийся с сигнатуры `MOXCEL`. Строки и ячейки кодируются так:

```
<кортеж строки> = {формат строки} , номер строки , высота , число ячеек , флаг
<ячейка>        = {данные ячейки} , номер колонки
```

Строке принадлежит ровно `число ячеек` ячеек. У первых `n-1` номер колонки указан
явно, а **у последней ячейки номер опущен**, причём запись с этой последней ячейкой
одновременно является кортежем следующей строки. Именно это наложение и делает формат
запутанным, поэтому разбор опирается исключительно на объявленные счётчики, а не на
догадки о том, где кончается строка.

Поэтому при вставке колонки нужно увеличить явные номера колонок после точки вставки,
увеличить число ячеек и — если вставка идёт в самый конец — сделать бывшую последнюю
ячейку явной. Удаление выполняет то же самое зеркально. Переименование подменяет текст
*внутри* существующей ячейки заголовка, чтобы больше ничего не сместилось.

Регистры находятся по строке заголовка (`Accumulation register "Имя"`), затем берутся
строка шапки и идущие за ней подряд строки данных той же ширины.

## Состав репозитория

```
mxl_column_editor.py        вся программа: парсер, движок правок, рендер, интерфейс
build_windows_exe.bat       сборка .exe в один щелчок
render_check.py / .bat      отдельный скрипт: рендерит файлы «до» и «после» через 1С
                            для сравнения бок о бок
onec/
  MxlToHtml.epf             одноразовая обработка (запасной вариант)
  MxlToHtml.bsl             её модуль формы
  MxlToHtmlService.epf      резидентная обработка (собирается вручную, см. выше)
  MxlToHtmlService.bsl      её модуль формы
  MxlRendererTemplate.dt    минимальная служебная ИБ
  README.md                 сборка и отладка обработок
```

Минимум для запуска — `mxl_column_editor.py` и папка `onec/` с двумя `.epf` и `.dt`.
